# PICHT_mcmr

Project-specific repository based on `MCMRSimulator.jl` for neuromelanin-sensitive MRI simulation experiments.

This repository contains a cleaned and reproducible version of the work performed during the lab immersion project. It combines:

1. a modified version of `MCMRSimulator.jl`;
2. step-by-step scripts to understand Julia and MCMR;
3. scripts to test triangular mesh substrates;
4. an implementation and validation of overlapping-sphere geometries;
5. reusable single-substrate DWI simulation scripts;
6. two-substrate cell + neuromelanin gradient-echo simulations.

The goal is to make the project reproducible and understandable for a supervisor or future user, from the first simulator tests to the final compartment-wise cell and neuromelanin signal simulations.

---

## Original MCMRSimulator

This repository is based on `MCMRSimulator.jl`, a Monte Carlo MRI simulator developed to model the effect of tissue microstructure on MRI signal evolution.

Official documentation:

- Dev documentation: https://open.win.ox.ac.uk/pages/ndcn0236/mcmrsimulator.jl/dev
- Stable documentation: https://open.win.ox.ac.uk/pages/ndcn0236/mcmrsimulator.jl/stable

This repository is not an official MCMR release. It is a project-specific working version containing additional scripts and modifications used for neuromelanin-sensitive MRI simulations.

Please cite the original simulator when using this work:


- triangular mesh substrate tests;

## Installation and setup

The project was developed using Julia 1.11.

From the repository root:

```bash
cd ~/project/PICHT_mcmr
```

Start Julia with the project environment:

```bash
julia +1.11 --project=.
```

Then instantiate the environment:

```julia
using Pkg
Pkg.instantiate()
```

Scripts can also be launched directly from the terminal:

```bash
julia +1.11 --project=. path/to/script.jl
```

All scripts should be run from the repository root.

Scripts:

```text
03_compare_non_overlapping_vs_overlapping.jl
04_long_cylinder_free_vs_restricted_diffusion.jl
utils_overlapping.jl
```

Expected input examples:

```text
substrate_generation/example_outputs/one_soma_list_new.swc
substrate_generation/example_outputs/cylinder_soma_neurons_list_new.swc
```

Run examples:

```bash
julia +1.11 --project=. docs/scripts/04_overlapping_spheres/01_create_overlapping_spheres.jl

julia +1.11 --project=. docs/scripts/04_overlapping_spheres/04_long_cylinder_free_vs_restricted_diffusion.jl
```

This folder validates that:

- SWC files can be converted into sphere-based substrates;
- `Spheres(..., overlapping = true)` can be simulated;
- overlapping and non-overlapping sphere behavior can be compared;
- a long cylinder-like geometry shows direction-dependent diffusion.

For the long-cylinder validation, the expected qualitative result is:

```text
ADC_x > ADC_y and ADC_x > ADC_z
```

because diffusion is less restricted along the long axis of the cylinder.

In diffusion MRI, stronger diffusion along the gradient direction causes stronger signal attenuation. Therefore, a higher ADC along the cylinder axis is expected.

# 06 — Two-substrate cell + neuromelanin simulation

Folder:

```text
docs/scripts/06_two_substrate_cell_neuromelanin/
```

Purpose:

Run the project-specific two-substrate simulation with:

1. a cell substrate;
2. a neuromelanin substrate.

Scripts:

```text
01_check_two_substrate_geometry_and_R1.jl
02_run_cell_neuromelanin_gradient_echo.jl
03_plot_cell_neuromelanin_signals.jl
utils_cell_neuromelanin.jl
```

Default input files:

```text
substrate_generation/example_outputs/cell_soma_r19_one_branche_neurons_list_new.swc
substrate_generation/example_outputs/neuromelanin_sphere_r15_neurons_list_new.swc
```

The combined geometry is always built in this order:

```julia
geometry = [
    cell_geometry,
    neuromelanin_geometry,
]
```

Therefore:

```text
geometry[1] = cell
geometry[2] = neuromelanin
```

This is important for compartment-specific readouts:

```julia
Subset(inside = true, geometry_index = 1)   # inside cell
Subset(inside = false, geometry_index = 1)  # outside cell
Subset(inside = true, geometry_index = 2)   # inside neuromelanin
```

Important interpretation note:

```text
inside cell
```

means all spins inside the cell geometry. If the neuromelanin region lies inside the cell, then neuromelanin spins may also be included in the inside-cell subset.

## Step 1: check geometry and local R1

Run:

```bash
julia +1.11 --project=. docs/scripts/06_two_substrate_cell_neuromelanin/01_check_two_substrate_geometry_and_R1.jl
```

Output:

```text
docs/data/processed/cell_r19_nm_r15_local_R1_check.csv
```

This script checks:

- both SWC files can be loaded;
- both geometries are created correctly;
- spins are generated in a common bounding box;
- inside/outside spin counts are reasonable;
- expected local R1 values are correct at selected points.

## Relaxation units

In these scripts, time is expressed in milliseconds.

Therefore, relaxation rates are expressed in `ms⁻¹`.

Examples:

```text
T1 = 1000 ms  -> R1 = 1 / 1000 ms⁻¹ = 0.001 ms⁻¹
T2 = 3 ms     -> R2 = 1 / 3 ms⁻¹ ≈ 0.333 ms⁻¹
```

In the two-substrate workflow, the intended local R1 behavior is:

```text
local R1 = global_R1
         + cell_R1_inside if inside cell
         + nm_R1_inside if inside neuromelanin
```

Some validation scripts use deliberately extreme R1 values, for example:

```text
R1 = 1.0 ms⁻¹
```

which corresponds to:

```text
T1 = 1 ms
```

Such values are useful for checking that the implementation works, but should not automatically be interpreted as biologically realistic.

## Notes and limitations

The scripts are designed for reproducibility and clarity, not maximum computational efficiency.

Some validation scripts use:

```julia
const MANUAL_TIMESTEP = 0.01
```

This can make simulations feasible for small spheres, but it should be considered an approximation and reported when interpreting results.

The example substrates are intentionally small. They are included to make the scripts runnable without relying on absolute paths to external folders.

Substrate generation itself was performed outside this repository using `Grow_neurons` and `syn_sim`. This repository only contains example output substrates and the simulation workflow.
